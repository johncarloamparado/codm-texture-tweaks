# CODM Blocky Textures: project handbook

Zygisk module for Call of Duty: Mobile (`com.garena.game.codm`) with a WebUI. Module id `codm_tex_logger`.
Source layout: `main.cpp` (native module), `webroot/index.html` (WebUI), `module.prop`, `customize.sh`, `tests/`, `.github/workflows/build.yml`.

## grass.txt (the list of hidden textures) - renamed hidden.txt in v0.70

- Since v0.70 the file is `hidden.txt` (same format, same 4096 limit; the old name was too narrow because effects such as smoke are hidden here too). The text below still says `grass.txt` in places: read it as `hidden.txt`. Internal names (`GRASSCAND`, `grass_rules`, `grassSel`, `g_grass`) did not change.
- Migration: the WebUI read script copies `grass.txt` to `hidden.txt` once when `hidden.txt` does not exist yet; the old file is left in place. The module reads `hidden.txt`, and falls back to `grass.txt` ONLY when `hidden.txt` does not exist (a phone that updated but did not open the WebUI yet). An existing empty `hidden.txt` means everything is off and never falls back. `CFGLIST` (backup / heal) lists both names.

- One rule per line: `<format> <width> <height> <64-bit hex fingerprint>`, all four must match exactly.
- At most **4096 unique** rules (unique by format, width, height, fingerprint). The module keeps the first 4096 and logs the rest as ignored. The WebUI refuses a 4097th unique rule *before* anything is written.
- `range ...` lines (v0.47 to v0.56) do not exist any more. The module skips and counts them; the WebUI drops them the first time it rewrites the file and shows a one time notice.
- Lines are `#` comments, blank, or exact rules. Old two-field lines (`format size`, v0.44) and broken lines are ignored, never guessed.
- The module builds one sorted vector when the settings are loaded and uses a binary search in the upload hooks (no allocation, read-only after load).
- The scope / reticle atlas and some lobby-button sizes are guarded against Hide/blanking by grass.txt. Per-texture look settings can still affect eligible guarded sizes; Restore candidates list them only when the native log captured them.

## WebUI behaviour that must not change by accident (v0.57.3)

- **A finder test is never ended by a switch.** In the test window (`#twOv`) a switch, `ON all`, `OFF all` and `Save` only *pause* the test (`gst.paused` / `gPend.paused`, kept in `ct_gst2` / `ct_gset`). While paused, grass.txt holds the person's own switches and may differ from the test list: `gLoadState` / `gLoadPend` skip the "grass.txt matches the test" check for a paused test. `Back to the test` (`gResume`, id `gfResume`, in the finder card only since v0.58.2) writes the test rules again. In the test window the way back is `ON all` (it writes keep + test keys, which is the same list as `gTestRules()`, so `gSameSet` resumes the test). When the switches become exactly the test list again (ON all, or switching the last one back, `gSameSet`), the test runs again by itself (v0.57.4). `End the test` (`gEndTest`, id `gfEnd`, finder card only since v0.58.2; the test window has no Back / End buttons any more) is the only way to end it on purpose, besides the old Cancel (`gfOff`). Do not bring the two buttons back into `#twOv`: the one `Return to last test` control (v0.59, finder card) is the way back after a test has ended. The answers (hidden / still there / back) are refused while paused.
- **Side test selection (v0.58.3).** One function, `twSideInfo()`, decides what a Side test switches off; the button label, the note `#twSideNote` and `twSide()` all read it. Ticked rows win over the search and filters. Nothing ticked + a chosen search / Format / Size / See-through = the matches (`twFiltered()`). Nothing picked, everything picked (n >= the test list) or `keep + picked` over 4096 = disabled with a reason (never silent). The fixed "With mips" is not a chosen filter (`twFiltersOn()`). The Side test also works while the test is PAUSED: the person's own switches are replaced by `gst.keep + sub.keys`, `gst.paused` becomes false; `hist / a / b / ta / tb / phase / name / grp / keep / U` are not touched, so "still there", Back and Cancel behave as before. A pending set (`gPend`) and an ended test cannot side-test.
- **Return to last test (v0.59).** ONE checkpoint, localStorage key `ct_gcp` (written only by `cpSave()`, read by `cpLoad()` at the end of `gLoadState`). "Last test" = the last finder test STEP that was shown to the person: a normal `gst` copy (keys only: `U`, `keep`, `a / b / ta / tb`, `phase`, `hist`, `sub`, `name`, `grp`) plus `why` (`end`, `cancel`, `found`, `fail`, `drop`), `found` (id of the saved texture / set, "" otherwise) and `sw` (the person's own switches, only when the test was PAUSED). Taken (`cpPut`, the old one is replaced) when the test is lost: End the test, Cancel, a texture found (`gConfirm`, the step BEFORE the last answer: `cpLast` pops the hist entry that answer pushed), a set kept (`gKeepSet`, why `found`), "nothing changed" (`gFail`), a pending set discarded / ended / cancelled (`gPend.cp` holds the last step: a / b / ta / tb / phase / hist). NOT covered, on purpose: the paused switches replaced by a Side test (the test itself is not lost then, and a second "return" during a running test would be confusing); "Turn all off" without a test; a search dropped by `gLoadState` because grass.txt no longer matches. Return (`gReturn`, button `#gfReturn`, only in the finder card when no test and no pending set is running; one button, the line under the label says "N textures, step S" and why it ended; no extra text that Short mode hides): refused while a test runs; the 4096 check (`MAXR`) comes BEFORE anything is written; writes exactly the test rules (`keep + slice` or `keep + sub.keys`), or `sw` for a paused checkpoint (then the test is paused again); if that would turn off switches the person has now, the first tap only arms ("Tap again: N of my switches will go back to normal", 5 s). After a Return the checkpoint is cleared. It is also cleared when the saved texture / set it found is deleted (`cpCheckFound`), and dropped silently when it does not validate (`cpValid`: keys, slice, phase, hist, sub inside U, 4096). Size: keys only, at most 400 KB (`sw` is dropped first, then the checkpoint); the page-settings backup skips a value over 150 KB like any other key. Not in the test window (`#twOv`), nothing on Home.
- **Saved sets are ONE container (v0.60).** A set saved with `Save as ONE set` (`libSaveSet`, used by `tbSave`, `twSave` and `gKeepSet`) is shown in My textures as ONE `<details class="item lib lib-set" data-set="ID">`: the summary has the name, `N textures`, the state (`hidden` / `partly hidden (n of N)` / `normal`) and the ONE switch (`.lib-sw`, `data-toggle`, it never opens or closes the container); the inside lists the members read only (format, size, short id; no switch, no name field per member) and has the name, the group and `Delete set` of the WHOLE set (`data-name`, `data-grpsel`, `data-forget`; the handlers write every line with the same set id). Single textures keep their row. The open / closed state is `gSetOpen` (memory only). The file format of `texlib.txt` did not change (`fmt w h hash group~setid|name`). Rules that must not change by accident: (1) `gLoadLib` calls `libNormalize()`: every line of a set gets the name and group of the FIRST line (so a set can never show twice, in two groups) and a set id with only one member is dropped (a lonely member is a normal texture, never \"1 textures together\"); if it changed something the file is rewritten once. (2) `libSaveSet`: a key that is already saved ALONE joins the new set (its old name is replaced by the set name, the note says so); a key that is a member of ANOTHER set blocks the save (nothing is written; `libSetBlock` gives the reason, it is checked before a test is paused in `twSave`, and Keep all in the finder card leaves the pending set as it is). `Save one by one` never moves or renames a texture that is already saved. A texture found again by the finder (`gConfirm`) stays in the entry it is in (`libAdd` refuses a duplicate). (3) The bulk delete (`libOffUnits`) takes a set only when ALL its members are OFF; a partly hidden set is not counted. (4) The one switch of a partly hidden set hides ALL members. The Texture browser and the test window are texture-level tools: they can still switch ONE member (the set then shows `partly hidden`; one tap on the set switch makes it whole again). Do not add a per-member switch, name or group to the container. `.lib-st` (not `.d`) carries the count and state so Short mode keeps them.
- **Compact lists (v0.60.1 / v0.60.2).** My textures rows, the Texture browser rows (`.tb-row`) and the test window rows (`.tw-row`) are compact (CSS only; the blocks "v0.60.1 Part 6A" and "v0.60.2 Part 6B" at the end of the CSS). Rules: no text below 12 px; controls and hit areas are measured in REAL px with getBoundingClientRect / elementFromPoint (the main page is inside `.view` with `zoom:.96` / `.92`, so 40 CSS px = 38 / 37 real px: use 44 CSS px there; the two windows #tbOv / #twOv are NOT zoomed); the hit area of `.tw-ck` / `.tb-sw` is a `::before` measured from the PADDING box (`.tw-ck::before{inset:-12px}` = 42 px for the 22 px box). Tapping a checkbox may move `scrollTop` by itself (scroll anchoring when the text above the list changes height): what must stay is the position of the row on the screen. Do not add per-member controls to a set container.
- **My textures only holds what the person saved.** `gLoadLib` must never add rules from grass.txt as "Unnamed N" (during a test grass.txt holds hundreds of test rules). Rules that are hidden but not saved are listed in the Texture browser ("Hidden now, not saved"); `tbUnsaved()` leaves out the textures of a running, not paused test.
- **Delete in My textures.** Every row has `Delete` (`data-forget`, also turns the texture back to normal). Two bulk buttons (`data-libdel`, two taps, 5 s to confirm): `Delete unnamed that are OFF`, `Delete all that are OFF`. Bulk delete never touches entries that are ON.
- **Mips filter = With mips only (v0.58.1).** The Texture browser (`bf.mips`, `#tbMips`) and the test window (`tw.f.mips`, `#twMips`) offer one choice, "With mips" (`c.lv >= 2`); there is no "Any mips" and no "No mips". `mipsNorm()` turns any old saved `ct_bf.mips` value (`any`, `no`, anything else) into `yes` when the page loads and rewrites `ct_bf`. The numbers in the Format / Size lists and the "Filter: F of T" text count only textures with mips. The finder's own setup (`sf.mips`, "Format, shape and mips") and the C++ matching are not part of this and did not change. `__ct.mvis()` (preview / tests only) = number of listed textures with mips.
- **Session summary header (v0.58.1).** The refresh button `#sref` sits right after the title (CSS `summary.ch>#sref`, `margin-right:auto`), the chevron is alone at the far end. Keep it that way at 320 to 411 px.
- **Size filter = width OR height.** In the Texture browser and in the test window a size of 64 matches `64xN` and `Nx64` (`hasSide`, `sideCounts`). The number in the option list counts every texture that has that width or height. The finder search setup (smallest / largest texture to hide) still works on the longest side, on purpose (it is a range).

## Action field — Hide vs Restore original (v0.61)

- `grass.txt` is the Hide list (the selected texture is made transparent); `orig.txt` is the Restore original list (leave that texture as the game made it). Both accept exact `fmt w h hash` rules and have a hard limit of 4096 unique rules. The two maps must not contain the same key in a normal UI flow.
- Each `texlib.txt` entry has an action: absent action means Hide for backwards compatibility; `~r` means Restore original. Set lines encode the action after the set id (`group~setid~r|name`); single Restore entries use `group~~r|name`. All members of a set must share the first member's name, group, and action.
- The next Save / finder Keep action is held in localStorage `ct_gact`; it is UI preference, not finder test state or checkpoint state. Page-settings backup packs `ct_*` keys, while settings-folder backup/heal/restore includes `orig.txt`.
- A Restore-ON texture must never be included in a test that hides textures. `setRules()` is a safety net and filters Restore entries. A checkpoint whose universe contains a key that has since become a Restore entry is stale and must be dropped silently.
- Restore original means preserve the normal in-game appearance of a user-selected texture. Treat every fingerprint as a candidate until the user confirms it in-game.

## Settings folder and backup (v0.57.5, must not change by accident)

- **The folder is sticky.** `findDir()` (WebUI) never picks a folder only because another path shows a newer log. For each Android user the paths `/data/data/<pkg>/files`, `/data/user/<id>/<pkg>/files` and `/data_mirror/data_ce/null/<id>/<pkg>/files` are one candidate group. The page picks by: evidence the folder is real (status written, marker `.ct_keep`, settings files present) first, then the **pinned** path, then the usual order (`/data/data`, `/data/user`, mirror), then the newest log. The pin is kept in `localStorage` (`ct_pin`, `ct_pinu`) and in `/data/adb/codm_tex_cfg/pin_u<id>`. The shell route that worked (`ct_wr`: direct / nsenter / su) is tried first next time.
- **Auto** in the Game copy card = the copy used before (`ct_pinu`), not "the one that ran most recently".
- **Backup.** `/data/adb/codm_tex_cfg/u<id>/` holds a copy of every settings file (`CFGLIST` in index.html; not `hooksafe`, not logs). `.ct_keep` in the game folder is the marker: if the marker is missing there but present in the backup, the folder was emptied or replaced, so the backup is copied back once (`healSettings`, runs once per folder per page load, toast "N files were put back") and the page then follows the files. After every queued write `backupSoon()` syncs changed files (1.8 s later, one run for many taps). Nothing in the backup is ever read back unless the marker is gone.
- **Page settings backup (v0.58).** Everything the WebUI keeps in the browser (`ct_*` keys: export name, open cards, tab, filters, finder test incl. paused, presets, names/groups copy, history, interface choices) is packed into one file, `/data/adb/codm_tex_cfg/u<id>/ui.b64` (base64 of a JSON object), by `uiFlush()` through `backupSoon()` (same 1.8 s timer; the settings sync stays the last command). Written only when changed, in pieces of 48 KB. Every chunk must return a success marker, the completed temporary file must have the exact expected byte count, and only a successful `mv` may report success; a failed chunk / length check / rename removes only `ui.tmp`, preserves the previous `ui.b64`, and leaves the backup dirty for a later retry. A value over 150 KB is skipped; `ct_hist` is dropped first above 300 KB. Not saved: `ct_pin`, `ct_pinu`, `ct_wr`, `ct_ui_stamp`, `ct_ui_msg`; never `hooksafe`, `fullsize`, `scale_crash`, logs. `Storage.prototype.setItem/removeItem` is wrapped so every `ct_` change marks the backup dirty. Restore (`uiRestore`, once per page load, after `healSettings`): only when `ct_ui_stamp` is missing (browser data wiped); keys that already exist are never overwritten; the stamp is set and verified BEFORE `location.reload()` so it can never loop. The export name is also saved on `change`.
- Do not put `echo OK` in these scripts (the test mocks answer anything that contains it).
- Report (`codm_diag.txt`) has `== folder candidates` and `== settings backup` sections for the next bug report.
- Speed: the candidate list is sorted once into `/data/local/tmp/ct_cand_u<id>` and the page keeps the result while the log size/time is the same; the Zygisk check is cached 90 s; `logcat` is only read when the status file is missing; no `backdrop-filter`, two meteors instead of four, no endless logo float.

## Rules for the code


- No `thread_local` object with a destructor in `main.cpp` (the Zygisk loaded `.so` aborts). `tests/run_host_tests.sh` has a lint for it.
- Never read the data pointer of a texture upload while a pixel unpack buffer is bound.
- The WebUI writes large rule/library files with `writeLinesAtomic` (pieces of 400 lines to `<file>.new`, checked write markers, line-count validation, then a success-gated `mv`). A failed write or rename must return failure and keep the previous destination intact. The page-settings `ui.b64` uses 48 KB chunks, checked writes and an exact byte-count check before replacement. One shell command must stay far below 128 KB.
- The texture list is read in chunks of 400 distinct `GRASSCAND` lines. Never cut it with `tail`.
- Class names `.sh`, `.sh-ov`, `.sh-h`, `.sh-x`, `.sh-s`, `.sh-list`, `.sh-foot` belong to the themed sheet in the WebUI.

## Persistence and regression pass (v0.63 / Part 9)

- `writeLinesAtomic()` accepts a write only when the shell return status is successful and the exact `WROTE` marker is present. Temporary chunks are chained with `&&`; line count is checked before replacement; `WROTE` is emitted only inside the successful `mv` branch. Failure cleans the temporary file and returns `{ ok: false }`, preserving the last destination file. Distinct markers are used rather than a generic `echo OK` (the UI test shell mocks must not mistake a failed command for a successful write).
- `uiFlush()` checks initialization and every 48 KB chunk write with the `UIWRITEOK` marker and shell status, verifies the `.tmp` file byte count against the exact encoded payload, and uses `UIOK` only after a successful atomic rename. Failure removes the temporary file, leaves the old `ui.b64` intact, clears the busy flag, and leaves the UI backup dirty for a later save / visibility-triggered retry; it does not loop retrying a persistent failure.
- `tests/persistence_test.js` exercises actual writer source with temporary directories and simulated write / rename failures; it also checks release version consistency, old library lines defaulting to Hide, explicit `~r` compatibility, the 4096 rule cap, pinned-folder preference, and settings backup allowlists.
- Part 9 does not introduce a new saved-data schema, so the existing migration contract remains unchanged: old `texlib.txt` records without action are Hide; `~r` is Restore original; saved set members normalize to the first member's metadata/action; checkpoint and browser settings keys remain backward compatible. Existing `ui_test.py` sections 17–26 remain the UI regression suite; the environment can still block the full suite before it reaches any assertions.

## Restore finder (Part 12; v0.65 / versionCode 86)

- The Texture browser and finder expose **Hide test** (default) and **Restore original test**. Old saved test states with no `mode` remain Hide/search. Restore-mode tests use the same first test, narrowing answers, Back, Side test, pause/reload, Return to last test and Keep flow as the Hide finder, but their native rule file is `orig.txt`; they never write a finder test into `grass.txt`.
- Restore mode asks **“Is the problem fixed?”**. **Yes** means the cause is in the restored half; **No** means it is in the other half. “Keep all” saves the found candidate(s) with action **Restore original** in My textures. Mode is persisted as part of finder state. Restore rules use the same atomic `writeLinesAtomic` path, retain last-good content on failure, and obey the 4096 unique exact-rule cap in `orig.txt`.
- `RESTORECAND` is separate from `GRASSCAND`: it logs distinct, compressed level-0 fingerprints at levels the native `tex_post` can affect (lv >= 3), including ETC2 RGB that cannot be made transparent by Hide. PBO-bound uploads are not inspected; a diagnostic explains this. Each candidate stream is read in chunks of 400 lines and reports an incomplete list. The UI's “With mips” filter is unchanged. The old Hide candidate/action behavior is not changed by the new stream.
- Native Restore original can undo tracked per-texture sampling, base/mip/LOD changes and module style/filter flags for the matched texture. It cannot undo the global render-scale setting or the module’s global anisotropy clamp (h_tp / h_tpf clamp values without saving/restoring the prior per-texture anisotropy): the Restore test explicitly tells the user this when no cause is found. Guarded sizes in `grass_guard()` are excluded only from Hide/blank operations; they may still be candidates for per-texture Restore if logged. The finder cannot test textures not captured in `RESTORECAND`, uploads behind a PBO, texture arrays/3D paths that do not reach this 2D hook, or effects other than per-texture texture modifications. A Restore result is only a candidate to verify in-game.
- Required verification: `sh tests/run_host_tests.sh`, `node tests/js_syntax_check.js`, `node tests/persistence_test.js`, and `python3 tests/ui_test.py`.
